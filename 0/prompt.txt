Before we do anything understand the agent we are trying to build , our goal is to then prep a dataset that can really star our agentic pruning approach ideally a subet ( to POC) that has I would focus on five types of difficult cases.









1. Semantic distance
The user describes the outcome without using any words from the tool description.
Example: "Make this clip listenable without the visuals." → audio extraction and format conversion.












2. Taxonomy collisions
Several tools have similar descriptions but belong to different functional categories or have different outputs.
Example: "Compare these monthly numbers." Candidates might include spreadsheet comparison, database querying, financial analysis, and chart generation.












3. Implicit multi-capability requests
The user describes one desired outcome that requires several tools.
Example: "Tell me whether my commute would be quicker if I moved closer to work." → location lookup, route estimation, and travel-time comparison.












4. Near-duplicate candidates
Several tools look equally relevant from their descriptions, but only some satisfy the actual constraints.
Example: "Show the trend over the last 30 days." A current-value lookup isn't sufficient; you need historical data.












5. Ambiguity and underspecification
Several interpretations are plausible, or an essential parameter is missing.
Example: "Send it to the team." The system must identify the likely communication capabilities while recognizing that the file and recipients may need clarification., if these cases dont do better in pruning right now its not worth it.
